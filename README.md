# ForkIQ SafeFork Controller

自托管的单人 GitHub 保存面板：追踪上游更新，但不让已有分支后退、不移动已有标签、不执行被保存项目的 CI。

基于 [zzusec/forkiq](https://github.com/zzusec/forkiq) 的独立改造，保留原 MIT 许可。原项目的镜像强推、合并、回滚、自动发现和工作流保活功能已移除。

## 保存规则

- 同步所有 `refs/heads/*`、原始 `refs/tags/*` 对象及可达历史；只允许创建和快进，不生成额外 merge commit。
- 登记已有仓库时，上游删除分支或标签仍保留目标已有引用；网页新建公开库采用下文的受管分支清理规则。上游消失、撤权、改名、同名重建或身份变化时停写，不自动更换来源。
- 分支回退、分叉、标签冲突、空文件树或异常大量删除时，整批停止。没有强推或绕过按钮。
- 可显式登记 `main → upstream-main`，旧 `main` 保持不动。目标独有分支、归档和 `sync-control` 保留。
- 已审核标签差异只能按“标签名、目标原始 SHA、上游原始 SHA”固定登记；旧标签不动，任一 SHA 变化后重新停写。
- 登记已有仓库保持暂停，先只读预览，10 分钟内确认后才启用；网页一键新建则在首次同步核验后自动启用。每次写入仍重新检查。只读 API 遇到短暂连接或服务端错误最多尝试 4 次，权限、限流和证书错误直接停写。结果不确定或写入时崩溃后需重新预览；推送不会自动重试。
- 正式同步先保存服务器裸 Git 仓库，再推送 GitHub。副本位于持久状态卷的 `repositories/<目标仓库ID>.git`，包含完整拟同步历史与目标独有引用；同步临时目录清理或容器重启不会删除它。副本保存失败就不推送 GitHub，GitHub 推送失败也不回退服务器副本。
- 已保存的服务器分支同样只能快进、标签不能移动。除已启用的受管过期分支清理外，本地独有引用保留。预览只检查，不创建或修改持久副本。服务器独有引用不会自动上传到被人另行删改过的 GitHub 目标，需人工审查恢复范围。
- 后续检查先从已验证的服务器副本复制完整对象，再向远端增量拉取，避免每轮重复下载历史。首次远端拉取的单次上限为 30 分钟；超时停写，不自动重试推送。
- 远端引用列表读取和临时仓库的 fetch 网络失败时最多尝试 3 次，间隔 1、2 秒；每次引用检查最多 60 秒，传输连续 60 秒低于 1 KiB/s 会中断。完整拉取达到 30 分钟上限不立即重复。
- 若本轮尚未记录持久保存/推送意图，网络读取耗尽后按 **1、5、15、30、60 分钟**延迟排队，最多额外重试 5 轮。每轮都重新验证身份、Actions、全部引用与历史；成功后清零。队列串行，预计时间可能顺延，重启保留退避时间；自然周期不会提前打断退避。权限、证书、限流、仓库不存在、资源、历史冲突及意图之后的失败仍停写。手动暂停取消重试；耗尽后需要预览确认。新建流程仅在创建请求发出前或首次保存前的只读阶段使用该机制，不自动重复创建或隔离写请求。

### 可选公开 Git 加速

容器设置 `FORKIQ_PUBLIC_GIT_MIRROR=https://gh-proxy.org`（也支持 `https://gh-proxy.com`，留空关闭）。仅用于经过官方身份和公开性核验的公开上游对象 fetch，不向加速器传递任何 GitHub 凭据或代理凭据。私有来源、目标读取和所有推送继续使用原官方地址。

完整 heads/raw tags 快照始终从 `github.com` 读取；加速器返回的引用须精确匹配该快照并通过对象检查，否则不采用，网络读取失败或快照不匹配时回到官方 fetch。镜像不参与删除分支的依据，不修改全局 Git 配置，不关闭 TLS 或跟随重定向。第三方可用性没有保证，不能取代官方连接和安全检查。

这些规则保存的是 Git 历史，不是整个 GitHub 项目的全量备份：不包含 Git LFS 实体、子模块仓库、Issues、Release 附件、Actions 数据或 GitHub 设置。普通快进也可能含不良代码；本工具不审查代码质量或保证项目内容安全。

## 公开与私有来源

| 来源 | 允许的目标 | 读取凭据 |
| --- | --- | --- |
| 公开仓库 | 身份固定的公开原生 Fork，建议名为 `原仓库名-SafeFork` | Git 对象匿名读取 |
| 私有仓库 | 经授权的独立私有仓库，不能是原生 Fork | 单独挂载的只读来源凭据 |

私有复制和上游删除、撤权后的留存均须有权授权者允许；访问权限本身不等于留存授权。私有来源不会降级发布到公开目标。独立仓库不依赖原生私有 Fork 网络，但仍受账号、平台规则与法律约束，不提供“永不删除”保证。

## 权限和 CI 隔离

被管理目标的 Actions 必须**持续全局关闭**，且不能有在途任务。日常同步只检查；网页创建流程使用单独 OAuth 初始化凭据关闭它刚创建并固定身份的目标。应用没有开启或触发 Actions 的入口。迁移前还须停用其他同步写入口，保持单写者。

专用 GitHub App 按管理员批准的范围安装；使用网页创建功能时需选择 All repositories，以覆盖未来新目标。程序仍只管理显式登记或提交创建的目标，不自动发现其他库：

- `Contents: write`、`Workflows: write`：保真推送 Git 内容，包括工作流文件；不意味着运行工作流。
- `Administration: read`、`Actions: read`、`Metadata: read`：核对开关、任务和身份；不授予上述两类写权限。
- 私有来源使用另一个只读凭据。不要导出本机 GitHub 登录令牌，也不要将凭据写入仓库或聊天。

本应用开发仓库自己的 CI 只测试、构建本应用，无生产凭据，和被管理仓库的 CI 是两回事。真实 GitHub App 权限组合及含工作流文件的写入，须在合成仓库试点通过后再接入生产。

## Docker 启动

需要可用的 Docker Engine / Compose、GitHub 出站网络，以及你控制的 HTTPS 地址（可为 `/SafeFork/` 子路径）。容量取决于各仓库完整历史大小；同步串行进行，每次使用临时裸仓库，至少保留 1 GiB 可用空间，且还要容纳源、目标历史及 Git 运算峰值。Compose 的 512 MiB 内存限制不是适用所有仓库的容量承诺。

CI 同时提供按提交命名的已验证镜像 artifact（保留 7 天），包含 `controller-image.tar.gz`、`image.json`、`smoke.json` 和 `SHA256SUMS`。资源较少的主机可在核对提交、CI 结论及校验和后 `docker load`，无需现场构建。容器测试用 128 MiB 硬限制运行 Web worker 和真实小 Git 任务，并记录峰值；该结果只适用于合成小仓库，生产仓库仍须单独测量。

```sh
export FORKIQ_PUBLIC_URL=https://fork.example.com
docker compose build
docker compose up -d
docker compose ps
```

默认仅绑定 `127.0.0.1:8792`，非 root、只读根文件系统、单 worker，无 Docker socket。首次设置完成前不要公开管理入口；先通过受控本机/SSH 隧道访问，设置至少 12 位密码，再接入自己的 HTTPS 反向代理。代理须正确设置 HTTPS 转发头，并限制管理访问；不要直接暴露容器端口。

共用现有 HTTPS 443 时，将 `FORKIQ_PUBLIC_URL` 设置为 `https://你的主机/SafeFork`，重建容器以应用路径配置；状态卷必须保留。把以下 location 加到既有 HTTPS server 中，无需新建公网端口：

```nginx
location = /SafeFork { return 308 /SafeFork/; }
location = /SafeFork/setup { return 404; }
location ^~ /SafeFork/ {
    # 不加末尾 /：保留请求中的 /SafeFork 前缀。
    proxy_pass http://127.0.0.1:8792;
    proxy_set_header Host $http_host;
    proxy_set_header X-Forwarded-Proto https;
    proxy_set_header X-Forwarded-For $remote_addr;
    access_log off;
    error_log /dev/null;
}
```

子路径区分大小写，仅允许字母、数字、下划线、连字符及路径分隔符。链接、表单、静态资源、状态轮询、App manifest 回调与会话 Cookie 均使用该前缀；迁移后需重新登录，不重置密码或 App。旧 App 如仍保存旧主页/回调地址，应在 GitHub App 设置中更新为新地址；已有 installation 凭据不依赖浏览器回调来同步。

1. 登录面板，在 GitHub 连接页创建**专用** App，选择批准的安装范围，完成安装并检测连接。
2. 在 GitHub 人工完成目标 Actions 隔离并等候在途任务结束。
3. 登记已有来源与目标，核对固定 ID、分支映射、标签例外与私有授权。
4. 点击“只读预览”，刷新查看全部引用计划；确认后再启用同步。

面板只展示显式登记仓库的检查结果，不导入旧 GitHub Actions 的运行历史。App 已连接但受管仓库为 0 时，表示尚未接管，不代表原仓库丢失或已经同步；不要同时开启旧 Actions 同步与新控制器。

默认每轮完成后等待 60 分钟，设置范围 1–1440 分钟；不依赖 GitHub schedule，也不保证每小时必定成功。网络、限流、容量、长任务和停机均可能延迟。没有上游 webhook 授权时不能保证“上游一推即同步”。

### 网页一键创建公开 SafeFork

仓库页选择“新建 SafeFork”。首次在“GitHub 创建授权”按页面列出的主页与回调 URL 注册传统 OAuth App，保存 Client ID/Secret，再完成 GitHub 网页授权。首次配置后无需复制 Token。`repo` 授权本身覆盖账号可访问的公开和私有仓库；本入口只接受匿名可见的公开上游，不提供私有创建，不导出本机 gh 登录令牌。

提交上游后，后台创建 `<原名>-SafeFork`（后缀只加一次），包含全部分支；固定两端 ID、核对公开 Fork 父关系、关闭目标 Actions 并确认无在途任务、对齐默认分支，再完整保存 Git 历史、首次同步及核验，最后启用已有自动调度。页面显示阶段与失败原因。重复点击复用同一任务；同名冲突或已有同源 Fork 会停止，不自动改名、覆盖或删除仓库。

元数据读取使用现有 App 的只读接口配额，并明确验证来源公开可见性；Git 内容仍匿名读取。账号的公开 Fork 冲突扫描只在后台执行一次，避免多 Fork 账号消耗匿名 API 配额或长时间阻塞网页提交；不枚举私有仓库。

新建库只清理“上次成功同步中存在、此次完整来源快照已不存在”的受管分支，且 GitHub 和服务器 SHA 都须与基线相同。普通原子 push 的精确旧 SHA 保护同时覆盖快进与删除；GitHub 删除回读成功后才清理服务器分支。不清理未知目标分支或标签，不自动调整默认分支变更，不新增归档分支，也不保证立即擦除不可达底层对象。历史回退、分叉及标签改写依然整批停写。现有登记记录不自动升级此策略。

OAuth 凭据保存为状态目录内 `oauth-credentials.json`（0600），不回显、不记录日志。支持到期令牌刷新；失效需重新授权。清除创建授权不会更换已有库的 App 同步凭据，可另到 GitHub 已授权应用页撤权。备份状态目录时，该文件与 App 私钥一样需要受控保管。

创建中断后可在任务页重新核对；创建响应丢失且未固定目标 ID 时，需要先人工核对后登记已有库，不盲目重发 POST。首次保存/推送结果不确定则进入仓库详情预览后确认恢复；已创建仓库保留，Actions 不会自动重新开启。容量预检以 GitHub size 为估计，首次持久化复制已验证对象，避免双进程重打包；仍需容纳完整对象和临时峰值，不能把预检视为磁盘配额。

单库预览或手动同步只处理所请求的仓库，不额外触发其他库，也不推迟原定的自动检查时间；到期的自动检查仍串行处理所有已启用仓库。

私有凭据以只读文件挂载到 `/run/secrets/<文件名>`，面板只填写文件名，不填写 Token。凭据需可由 UID `10001` 读取，仅授权来源 `Contents: read`；禁止与目标写入凭据相同。挂载配置及真实值不得提交。

默认 Compose 不挂载私有凭据。需要私有来源时，先在主机上准备受限目录及凭据文件，再使用可选覆盖配置：

```sh
export FORKIQ_SOURCE_SECRETS_DIR_HOST=/absolute/path/to/source-secrets
docker compose -f compose.yaml -f compose.private.example.yaml up -d
```

路径必须已存在，配置不会自动创建目录；不要把整个用户主目录或其他无关密钥目录挂载进去。

持久状态在 `state` 卷；App 私钥默认位于其中。首次连接后可将私钥迁至单独受控的只读挂载，并设置 `FORKIQ_PEM_PATH`；之后不能直接从页面覆写只读私钥，轮换须停写并受控更换。备份状态应停机或使用 SQLite 一致性备份，不能只复制运行中的 `.db` 而忽略 WAL；含私钥的备份须加密、限制访问。

需要离线读取时，在受控 SSH/主机权限下使用普通 `git clone /实际状态目录/repositories/<ID>.git`；不要执行 `docker compose down -v` 或删除状态卷。副本 HEAD 指向登记的主分支（有映射时指向映射分支）。不要手动改写副本 refs、配置或身份文件；意外变化会停写，不能强推“修复”。

## 故障处理

检查仓库“需关注”状态、事件和最近检查时间；`/healthz` 同时检查 worker 活性，不只是 Web 进程。失败后先核对来源、权限和目标引用，再运行只读预览。不要用强推、移动标签、清库或重新开启 Actions 来“修复”。

暂停阻止后续推送，但不能撤回已发出的 Git 请求。GitHub Actions 开关、仓库可见性与 Git push 不是一个原子事务：管理员在检查之后改变这些设置仍可能破坏隔离。同步期间必须保持设置稳定，禁止并行管理操作；详见 [安全边界](SECURITY.md)。

从原版迁移应使用**独立状态目录**，逐库重新登记和审核，不直接复用启用状态。若误打开旧数据库，迁移会留存第一份 `.before-safefork` 副本、暂停全部旧记录并清除旧任务；不会自动迁移来源、私钥权限或创建远程仓库。历史备份表和文件保留，但不再提供回滚入口。

## 本地测试

Python 3.11/3.12、Git、Node.js：

```sh
python -m venv .venv
.venv/bin/pip install -r requirements.lock
.venv/bin/python -m unittest discover -s tests -p 'test_*.py'
node --test tests/test_ui.js
python deploy/container_smoke.py --image forkiq-safefork-controller:local
```

Windows 将 `.venv/bin/` 替换为 `.venv\Scripts\`。单元和真实 Git 测试仅使用合成数据；容器验收创建临时本地卷，不注入 GitHub 凭据。测试不能替代真实 GitHub App 的受控试点、24 小时自然调度观察和独立异地备份。
